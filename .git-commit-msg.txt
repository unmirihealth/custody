feat(tools): the six built-in MCP tools

catalog.list, sql.query, shell.run, files.write, files.export,
approvals.status -- each a plain function taking a ToolContext, each
calling Gateway.authorize before doing anything (except
approvals.status, which is read-only introspection on an approval id
the agent already holds, see that module's docstring for why it's the
one exception).

sql.query runs DuckDB inside the sandbox against docker/sandbox.Dockerfile
(python:3.12-alpine + duckdb, built locally as custody-sandbox:duckdb,
see docs/demo.md for the build step). A blunt SELECT/WITH-only
allow-list rejects writes and statement chaining before anything
reaches the sandbox; the real security boundary is still the sandbox
itself (read-only mount, no network, ephemeral container), not this
check. A GROUP BY result (every row carrying an integer "count"
column) goes through OutputGuard before it reaches the caller; any
other shape passes through, row-level access to identified data is
already gated by the approval flow upstream.

Added SandboxExecutor.run(image=...) to override the configured image
per call, so sql.query doesn't need a second executor just to point at
a different image than shell.run's.

files.write/files.export resolve every path against the workspace
directory and reject anything that would escape it (../../etc/passwd
style), tested directly.

Also cleaned up a redundant import in sandbox/executor.py while
chasing ruff's import sorting: docker.errors doesn't need a separate
explicit import, docker/__init__.py already exposes it as
docker.errors.

96% coverage. ruff and mypy --strict clean across all 32 source files.
156 tests passing total.
