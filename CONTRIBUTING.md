# Contributing

Custody handles oncology data workflows, even in its examples and tests.
A few rules exist because of that, before the usual ones.

## No real patient data, anywhere

Every fixture, example, and test dataset in this repository is synthetic,
generated by the project's own generator with a fixed seed. Never attach
a real clinical dataset, a real de-identified export, or a screenshot
containing real patient information to an issue, a pull request, a commit
message, or a code comment. If you are reporting a bug you hit against
real data at your institution, reproduce it with synthetic data first, or
describe it without a concrete dataset.

## Sign your commits (DCO)

Every commit must include a `Signed-off-by` trailer (`git commit -s`),
certifying you wrote it or otherwise have the right to submit it under
this project's license.

## Development setup

```bash
uv sync --extra dev
uv run pytest
uv run ruff check .
uv run mypy src/custody
```

## Where things live

See the architecture diagram in README.md and the module docstrings
under `src/custody/` for what each component is responsible for before
adding code to it. docs/threat-model.md is the other required read before
touching `custody.audit`, `custody.sandbox`, or `custody.guard`, since
those three are where a mistake would actually leak something.

## Pull requests

Keep them small and scoped to one change. Tests are required for any new
policy decision path, including deny paths, see the existing test suite
once it lands for the pattern. CI runs lint, type check (mypy strict on
`src/`), and tests on Python 3.12 and 3.13.
